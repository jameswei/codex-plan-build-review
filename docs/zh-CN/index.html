面向 Codex 的角色化工作流

用证据推进重要里程碑，而不是依靠猜测。

将规划、实现与审查分离。让每个范围决策都清晰可见，每项任务都经过独立检查， 并由你掌控每一次发布。

在 GitHub 上查看 安装技能

里程碑路径

  1. 01规划以仓库中的真实证据为基础。
  2. 02审查通过独立的计划审查。
  3. 03批准停下来等待用户明确决定。
  4. 04构建每次只实现一项边界清晰的任务。
  5. 05验证逐项审查、验证并创建检查点。

4个专注角色

2个明确批准关口

1项进行中的任务

0次自动合并

有意分离职责

一个工作流，四个专注角色。

每个代理只承担边界清晰的职责，并且只获得完成职责所需的权限。

01

探索者

在规划前执行范围明确、以只读为主的调查。

只读Terra · medium
02

规划者

把用户意图和仓库证据整理成决策完整的计划。

只读Sol · xhigh
03

构建者

每次只实现一项已批准、可独立审查的任务。

工作区写入Sol · medium
04

审查者

独立检查计划、任务变更和最终集成结果。

只读Sol · high

内置保障

过程始终清晰可查。

A

批准前先审查

只有独立审查者通过计划后，用户才会看到并决定是否批准。

B

每项任务都创建检查点

当前变更完成验证、审查和提交之前，不会开始后续任务。

C

发布前完成集成审查

在请求发布批准前，最终审查会检查跨任务契约和整体行为。

随时可以开始

安装一次，明确调用。

克隆技能并安装它的角色定义，然后启动一个新的 Codex 会话。 

git clone https://github.com/jameswei/codex-plan-build-review.git \
  ~/.codex/skills/plan-build-review

mkdir -p ~/.codex/agents
cp ~/.codex/skills/plan-build-review/assets/agents/*.toml \
  ~/.codex/agents/

$ 使用 $plan-build-review 交付这个里程碑。
