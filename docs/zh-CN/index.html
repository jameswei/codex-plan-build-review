面向 Codex 和 Claude Code 的角色化工作流

用证据推进边界明确的工作，而不是依靠猜测。

将规划、实现与审查分离。在细化计划前挑战其前提，让每项任务都经过独立检查， 并由你掌控每一次发布。

工作路径

  1. 01规划以仓库中的真实证据为基础。
  2. 02审查通过独立的计划审查。
  3. 03批准停下来等待用户明确决定。
  4. 04构建每次只实现一项边界清晰的任务。
  5. 05验证逐项审查、验证并创建检查点。

有意分离职责

一个工作流，四个专注角色。

每个代理只承担边界清晰的职责，并且只获得完成职责所需的权限。

01

探索者

在规划前执行范围明确、以只读为主的调查。

02

规划者

把用户意图和仓库证据整理成最小而决策完整的计划。

03

构建者

每次只实现一项已批准、可独立审查的任务。

04

审查者

先挑战前提，再独立检查计划、任务变更和累积风险。

每个角色都有与职责匹配的 model 和 reasoning effort 配置。请在 README 中查看不同 runtime 的具体配置。

内置保障

过程始终清晰可查。

A

批准前挑战

审查者必须同时通过计划前提和规格，计划才可进入批准阶段。

B

为完整行为创建检查点

当前变更可独立正确，并完成验证、审查和提交前，不会开始后续任务。

C

仅在风险需要时进行集成审查

只有能增加覆盖时，独立最终审查才检查跨任务契约。

随时可以开始

安装一次，明确调用。

Claude Code 一步即可安装技能和全部四个角色，无需手动复制文件； Codex 在安装技能之外，还需要一步手动操作来安装它的自定义代理。 只读权限的实现方式也不对等：Codex 会在操作系统层面沙箱化写入 操作，而 Claude Code 的只读角色只是没有被授予 Bash 或 MCP 工具。

Codex

git clone https://github.com/jameswei/plan-build-review.git \
  ~/.codex/skills/plan-build-review

mkdir -p ~/.codex/agents
cp ~/.codex/skills/plan-build-review/assets/agents/*.toml \
  ~/.codex/agents/

$ 使用 $plan-build-review 交付这个 feature 或 milestone。

/plugin marketplace add jameswei/plan-build-review
/plugin install plan-build-review@plan-build-review
/reload-plugins

$ 使用 /plan-build-review:plan-build-review 交付这个 feature 或 milestone。
